# 项目结构：dsh-develop-ui

> 依据 `specs/技术栈.md`（dual-half 模型）、`specs/开发规范.md`（第 4 节）制定
> 文档版本：v1.0 ｜ 状态：初始化基线

## 架构模式

**混合架构**：外层按半区（host / client）组织，内层按特性模块组织。DSH 插件无官方脚手架，采用手动结构，与 DSH 官方包（`src/host` + `src/client` + `exports["./client"]`）对齐。

## 目录树

```
dsh-develop-ui/
├── package.json              # dsh.client.inject + exports + peerDependencies + dsh.bundle.patch
├── cordis.patch.yml          # bundle patch：insert 本插件行（profile bundle 加载必需）
├── tsconfig.json             # strict，双半共享编译基线
├── build.mjs                 # esbuild 双入口构建脚本（host ESM / client __ModuleLoader__ lazy-CJS）
├── .gitignore
├── README.md
├── specs/                    # 产品文档（产品概述/技术栈/开发规范/开发路线图/项目结构）
├── docs/
│   ├── 开发记录/              # 初始化记录、M0-技术验证、迭代日志
│   ├── 测试报告/
│   └── 发布记录/
├── src/
│   ├── shared/               # 双半共享：RPC 契约类型、常量、错误码（纯类型）
│   │   ├── rpc.ts            # ctx.remote 服务契约与出入参类型
│   │   ├── errors.ts         # 错误码（FS_NOT_FOUND / FS_STALE_VERSION …）
│   │   └── constants.ts      # MAX_FILE_SIZE_BYTES、隐藏文件规则等
│   ├── host/                 # host 半（Node 侧，可自由 import npm 包）
│   │   ├── index.ts          # apply(ctx)：@Remote 服务注册（fs/md）
│   │   ├── fs-service.ts     # ctx.fs 封装：listDir/stat/readText/writeText + 路径边界
│   │   ├── markdown.ts       # markdown-it + 任务列表 → HTML
│   │   └── highlight.ts      # shiki 代码高亮
│   └── client/               # client 半（__ModuleLoader__ lazy-CJS，require react/@deepseek-ai/*）
│       ├── index.ts          # apply(ctx)：注册 sidebar 面板 + details 内容 + conversation 插槽
│       ├── services/         # ctx.remote 封装（fsApi / mdApi）
│       ├── filetree/         # sidebar 文件树面板 + useFileTree hook
│       ├── content/          # details 列文件内容（查看/编辑/预览）
│       ├── editor/           # textarea 编辑 + dirty 标记 + Ctrl+S
│       ├── preview/          # md 源码/预览切换
│       └── conversation/     # conversation additive 插槽（@文件 引用等）
└── tests/
    ├── unit/                 # 纯函数/服务测试（fs-service、markdown 渲染）
    └── integration/          # client bundle 格式冒烟、RPC 契约测试
```

## 依赖规则

```
src/shared ← src/host、src/client（共享层可被双半依赖）
app 层（client 半）→ services → hooks → components（上层依赖下层）
```

- **host 半与 client 半禁止互相 import**，仅通过 `src/shared/rpc.ts` 定义的类型契约通信（host 注册 `harness.handle`，client 调 `host.call`）
- `src/shared/` 保持纯类型与常量，禁止任何运行时逻辑
- client 内部：`components`（渲染，无逻辑）→ `hooks`（逻辑）→ `services`（唯一 host.call 入口）
- 样式仅经 `styles.insert`（client 半闭包约束），不建 CSS 文件树

## 目录职责表

| 路径 | 职责 | 边界 |
|------|------|------|
| `src/shared/` | RPC 契约、错误码、常量 | 纯类型，双半共享 |
| `src/host/` | 文件系统、md 渲染、高亮 | 唯一允许 import npm 库与 `ctx.fs` |
| `src/client/` | 三栏 UI、文件树、编辑、预览、对话 | 闭包约束：ctx 服务 + host.call + styles.insert |
| `build.mjs` | esbuild 双入口（host 外部化依赖 / client 闭包白名单） | 构建唯一入口 |
| `tests/unit` | 纯逻辑测试 | 不依赖 DSH 运行时 |
| `tests/integration` | RPC 契约与安装冒烟 | 需要 DSH 运行时 |

## 约定

- 产物：`lib/index.js`（host）、`lib/client.js`（client）、`lib/types/**/*.d.ts`
- 提交：`specs/` 与 `docs/` 与源码同仓管理
