# 开发规范：dsh-develop-ui

> DeepSeek Harness dual-half 客户端插件 ｜ 依据 `specs/技术栈.md` v1.1 制定
> 文档版本：v1.0 ｜ 状态：规范制定完成

## 0. 规范适用范围与裁剪说明

本规范适用于 dsh-develop-ui（DSH Cordis 双半插件）的全部代码。**模板规范中以下条目对本项目不适用，已裁剪**：

| 裁剪项 | 原因 |
|--------|------|
| Java 五层架构 / @Autowired / Mapper / Liquibase / BasePage | 无 Java 后端，host 半为 TypeScript |
| 数据库固定字段 / 外键禁止项 / BOOL 禁止项 | 无数据库，文件即数据 |
| 响应式断点 / 移动优先 / 表格→卡片适配 | DSH 为 Electron 桌面固定窗口，无移动端 |
| 多环境 dev/test/prod / 环境变量部署 | 插件随 DSH 桌面分发，无独立部署环境 |

## 1. 技术栈基线

- **语言**：TypeScript 5.x，`strict: true`，全量类型标注，禁用 `any`（例外：`unknown` 收窄）
- **模块**：ESM（`"type": "module"`）
- **框架**：React 18.3.x（仅浏览器半，闭包符号）
- **插件框架**：`@deepseek-ai/cordis` ^4.0.1，dual-half 模型
- **构建**：esbuild ^0.28，双入口（host / client）
- **包管理**：pnpm
- **依赖版本**：所有 `@deepseek-ai/*` peerDeps 锁定 `0.1.0-rc.7` 起步（当前运行时为 DSH Desktop 2.0.10 / dsh 0.1.5-rc.2）；client 半新增外部模块前必须核对宿主平台 seed 表（§4.4）

## 2. 代码风格（TS/ESM）

| 规则 | 要求 |
|------|------|
| 缩进 | 2 空格 |
| 换行 | LF；编码 UTF-8 |
| 最大行宽 | 100 字符 |
| 引号 | 单引号 |
| 分号 | 必须 |
| 尾逗号 | 必须（多行） |
| 导出 | 具名导出优先，默认导出仅插件入口 `apply` |

```ts
// ✅ 正确
import { Service } from '@deepseek-ai/cordis';

export function apply(ctx: Context): void {
  ctx.on('ready', () => registerHandlers(ctx));
}

// ❌ 错误
import {Service} from "@deepseek-ai/cordis"
export default function apply(ctx){ ctx.on('ready', ()=>registerHandlers(ctx)) }
```

## 3. 命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| 变量/函数 | camelCase | `fileTree`、`loadFileList()` |
| 组件 | PascalCase | `FileTreePanel`、`MarkdownPreview` |
| 类/服务 | PascalCase | `FileSystemBridge`、`MarkdownRenderer` |
| 常量 | UPPER_SNAKE_CASE | `MAX_FILE_SIZE_BYTES` |
| 类型/接口 | PascalCase 前缀 `I` 不用 | `FileNode`、`SaveResult`（不用 `IFileNode`） |
| 组件文件 | PascalCase.tsx | `FileTreePanel.tsx` |
| host 模块文件 | camelCase.ts | `fileBridge.ts`、`markdown.ts` |
| RPC 方法 | `域.动作` 小写点分 | `fs.listDir`、`fs.writeText`、`md.render` |
| RPC 错误码 | 大写 + 下划线 | `FS_NOT_FOUND`、`FS_STALE_VERSION` |

```ts
// ✅ 正确：RPC 方法名表达"域.动作"
harness.handle('fs.listDir', listDir);

// ❌ 错误：无域前缀的模糊命名
harness.handle('getFiles', listDir);
```

## 4. dual-half 插件结构规范（本项目核心）

### 4.1 目录与导出契约

```
dsh-develop-ui/
├── src/host/       → 编译为 lib/index.js（exports["."]）
├── src/client/     → 编译为 lib/client.js（exports["./client"]）
├── src/shared/     → 双半共享的纯类型/常量（编译为 lib/types）
└── package.json    → dsh.client.inject + exports + peerDependencies
```

- `exports` 必须声明 `.` / `./client` / `./types` 三个子路径，各带 `types` 与 `default`
- host 半 `main` 指向 `lib/index.js`

### 4.2 半区职责边界（红线）

| 能力 | host 半（Node） | client 半（__ModuleLoader__ lazy-CJS） |
|------|----------------|----------------------------------------|
| import npm 包 | ✅ 允许（dependencies） | ⚠️ 仅宿主模块表**平台 seed** 命中的模块名（`react`/`react-dom`/`react/jsx-runtime`/`@deepseek-ai/dsh-client-store`/`@deepseek-ai/dsh-client-ui-slots`/`@deepseek-ai/dsh-client-ui-primitives`/`@deepseek-ai/dsh-client-ui-dockkit`/`@deepseek-ai/cordis`）或 `dsh.client.inject` 声明的图内包（如 `@deepseek-ai/dsh-client-ui-conversation`）；任意第三方 npm 包不可 import（除非打包进 bundle） |
| 文件系统 | ✅ 唯一入口（ctx.fs） | ❌ 禁止 |
| 网络 fetch | ✅ | ✅ 仅同源 API |
| 定时器 | ✅ | ✅ |
| 状态管理 | 不需要 | ✅ React Context/useReducer |
| 样式 | — | ✅ `styles.insert` 或注入样式 |

```ts
// ✅ 正确：client 半只做 UI，数据经 ctx.remote 调用 host @Remote 服务
const files = await ctx.remote.fs.listDir({ path });

// ❌ 错误：client 半尝试 import 运行时第三方 npm 包（宿主模块表无此模块）
import { markdownit } from 'markdown-it';
```

### 4.3 package.json 声明

```jsonc
// ✅ 正确：dsh.client.inject 声明浏览器半依赖注入图（仅列真正需要的图内包，seed 无需列）
//          + dsh.bundle.patch 声明 profile bundle 加载
{
  "dsh": {
    "client": {
      "inject": [
        "@deepseek-ai/dsh-client-store",
        "@deepseek-ai/dsh-client-locale",
        "@deepseek-ai/dsh-client-ui-primitives",
        "@deepseek-ai/dsh-client-ui-conversation"
      ],
      "platform": "web"
    },
    "bundle": {
      "patch": "./cordis.patch.yml"
    }
  },
  "peerDependencies": {
    "react": "^18.2.0",
    "@deepseek-ai/cordis": "^4.0.1"
  }
}
```

- inject 声明与实际用到的 ctx 服务必须一一对应，禁止多声明未使用项（影响加载图）
- peerDeps 的 React 必须 `^18.2.0`（与 DSH 一致），**禁止**直接依赖 React（防双实例）

### 4.4 client 半外部模块面（平台 seed / 图内包，硬约束）

client 半 bundle 里的每个 `require(spec)` 要么命中**平台 seed 表**（shell 内核预置的静态模块），
要么命中 `__DSH_BOOT__` 图内包名（子路径 `/client` 会被剥除后查表）。两者都不命中时，
模块表**同步抛错** → 整个 client 半 factory 物化失败 → 插件条目不激活（apply 从未执行）。

- DSH Desktop 2.0.10（dsh 0.1.5-rc.2）平台 seed：`react`、`react/jsx-runtime`、`react-dom`、
  `react-dom/client`、`@deepseek-ai/cordis`、`@deepseek-ai/dsh-client-store`、
  `@deepseek-ai/dsh-client-ui-slots`、`@deepseek-ai/dsh-client-ui-primitives`、
  `@deepseek-ai/dsh-client-ui-dockkit`
- 跨 DSH 版本升级后**必须重核**：`@deepseek-ai/dsh-client-runtime` 在 0.1.5-rc.2 已不存在
  （`defineStore` 迁到 `@deepseek-ai/dsh-client-store`），`dsh.client.runtime/client` 这类旧路径会直接炸启动
  （2026-09-16 事故：见 `docs/开发记录/DSH-2.0.10-启动失败修复.md`）
- 回归防线：`node tests/integration/client-bundle-format.test.mjs` 会对 `lib/client.js` 的
  require 面做白名单断言（新增依赖时必须同步白名单）

## 5. RPC 通信契约（@Remote 服务 ↔ ctx.remote）

1. **服务注册**：host 半用 `@Remote` 装饰器（typert）注册服务（如 `DynamicCordisRunner.getClientCode` 模式），client 半经 `ctx.remote.<namespace>.<method>` 调用。方法名 `域.动作`（`fs.listDir`、`md.render`）。
2. **序列化**：出入参与返回必须 JSON 可序列化（plain object / string / number / boolean / null）。禁止传函数、类实例、`Date` 原样（转字符串）。
3. **错误**：host 半抛出 `{ code, message }` 形状的错误（`code` 用 UPPER_SNAKE 错误码）；client 半统一捕获并展示 `message`，错误码用于分支判断。
4. **类型共享**：出入参类型定义在 `src/shared/`，host 与 client 双半引用同一份类型，禁止各自复制。

> 注：`harness.handle` / `host.call` 仅适用模型驱动动态包（clientCode eval），本插件为 bundle 静态包，不使用（见 `docs/开发记录/M0-技术验证.md`）。

```ts
// ✅ 正确：出入参为 JSON 可序列化对象，错误带码
export interface FsListResult { entries: Array<{ name: string; isDir: boolean }>; }

// ❌ 错误：返回 Date/函数等不可序列化值
return { mtime: new Date() };
```

## 6. 文件系统与安全规范

1. **唯一通道**：所有文件读写必须走 host 半 `ctx.fs`（`@deepseek-ai/dsh-fs`），禁止在 host 半直接用 Node `fs` 裸写。
2. **写操作版本守卫**：`writeText(target, content, expected)` / `editText(target, edit, expected)` 必须携带上次 `stat`/`readText` 拿到的版本；捕获 `FS_STALE_VERSION` 后提示用户冲突，禁止静默覆盖。
3. **路径边界**：所有路径经 `ctx.fs.resolve()` 解析后再操作；展示给用户前做 `contains()` 检查，防止越出工作区。
4. **大文件保护**：`readText` 前先 `stat`，超过 `MAX_FILE_SIZE_BYTES`（默认 1MB）拒绝读取并提示（文案指向"用外部编辑器"）。
5. **沙箱策略**：写操作被沙箱拒绝（`FsError` 权限码）时，UI 给出明确提示并引导用户调整会话权限，禁止绕过。
6. **目录列表**：`listDir` 返回稳定排序（目录优先、名称升序）；忽略隐藏文件（`.git` 等，白名单可配）。

```ts
// ✅ 正确：带版本守卫的保存
const result = await ctx.fs.writeText(target, content, expectedVersion);

// ❌ 错误：无版本守卫的裸写（可能覆盖他人/会话的并发修改）
await ctx.fs.writeText(target, content);
```

## 7. React 组件规范

### 7.1 原则与模式选择

- 七大设计原则（SRP/OCP/LSP/ISP/DIP/LoD/CRP）在 React 中的落地：组件单一职责、Props 接口最小化、依赖经 ctx/Props 注入（DIP）、禁止组件间直接访问对方内部状态（LoD）。
- 模式选择（按复杂度递进）：

| 场景 | 方案 |
|------|------|
| 简单局部状态 | `useState` |
| 中等复杂度逻辑 | 自定义 Hooks（`useFileTree`、`useEditorDirty`） |
| 跨组件共享（布局/选中文件） | Context + useReducer |
| 会话级数据 | 经注入的 ctx 服务（conversation/workspace） |

### 7.2 文件结构（导入 → 类型 → 组件）

```tsx
// ✅ 正确
import { useState } from 'react';            // 1. 导入
import type { FileNode } from '../shared';    // 2. 类型
interface FileTreeProps { root: string; }     // 3. Props 接口
export function FileTreePanel(props: FileTreeProps) { ... }  // 4. 组件
```

- Props 一律 `interface`（不用 `type`），函数组件 + Hooks，禁止 class 组件
- 组件内业务逻辑抽到自定义 Hooks；组件仅做渲染与事件分发
- 样式仅通过 `styles.insert` 注入（闭包约束），禁止 `import './x.css'`

## 8. 构建与依赖规范

- **构建**：esbuild 双入口脚本 `build.mjs`：
  - host 入口 `src/host/index.ts` → `lib/index.js`（依赖外部化，不打包 `@deepseek-ai/*`）
  - client 入口 `src/client/index.ts` → `lib/client.js`（**只允许闭包符号与注入服务**，构建时用 external 白名单约束，防止误打包 npm 依赖）
  - `format: 'esm'`，`target: 'es2022'`，生成 `.d.ts`（tsc `--emitDeclarationOnly` → `lib/types/`）
- **类型**：`exports.*.types` 指向 `lib/types/**/*.d.ts`
- **依赖纪律**：
  - host 半依赖（markdown-it、shiki 等）放 `dependencies`
  - DSH 生态包与 React 放 `peerDependencies`（版本对齐 rc.7 / ^18.2.0）
  - 禁止 lockfile 中出现两个 React 实例（`pnpm why react` 校验）

## 9. Git 工作流

- **分支**：`feature/[功能]`、`fix/[问题]`、`release/[版本]`；个人项目主干直接开发可简化，但提交信息仍遵守规范
- **提交格式**：`<type>(<scope>): <subject>`

| Type | 用途 | 示例 |
|------|------|------|
| feat | 新功能 | `feat(filetree): 支持目录折叠` |
| fix | 修复 | `fix(save): 修复版本冲突静默覆盖` |
| docs | 文档 | `docs(specs): 补充产品概述` |
| refactor | 重构 | `refactor(bridge): 抽取 fs 服务层` |
| test | 测试 | `test(md): 增加 gfm 表格用例` |
| chore | 构建/工具 | `chore(build): 升级 esbuild` |

- `specs/` 文档与源码同仓管理，文档变更用 `docs(specs)` 提交

## 10. AI 协作协议 Checklist

开发与 AI 协作时必须逐项勾选：

- [ ] 遵循第 2/3 节全部命名与风格约定（2 空格、单引号、分号、camelCase/PascalCase）
- [ ] TypeScript strict，禁止 `any`（用 `unknown` + 收窄）
- [ ] 每个导出函数有 JSDoc 注释（含参数与返回说明）
- [ ] 遵循 dual-half 边界：client 半仅 `require("react")`/`require("@deepseek-ai/*")`（external），不 import 第三方 npm 包
- [ ] client 半能力仅经 ctx 注入服务、`ctx.remote`、`styles.insert`
- [ ] RPC 方法名带域前缀，出入参 JSON 可序列化，类型定义在 `src/shared/` 共享
- [ ] 所有文件写操作走 host 半 `ctx.fs` 且带版本守卫，捕获 `FS_STALE_VERSION`
- [ ] 大文件（>1MB）读取前 stat 拦截
- [ ] 依赖纪律：DSH 生态包/React 放 peerDependencies，版本对齐 rc.7
- [ ] 组件为函数组件 + Hooks + Props interface，样式仅 `styles.insert`
- [ ] 提交信息符合 `<type>(<scope>): <subject>` 格式
- [ ] 功能完成后运行构建与类型检查（`pnpm build` + `tsc --noEmit`），确认零错误再提交
