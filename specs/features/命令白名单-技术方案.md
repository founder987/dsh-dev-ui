# 命令白名单 · 技术方案

> 依据：`specs/features/命令白名单.md` v1.1（决策点已确认：多粒度/全局/仅 shell 类）｜ 文档版本：v1.1 ｜ 状态：待 spike 验证项确认后实施

## 1. 总体设计

插件在 `conversation.composer` chain 槽注册一个接管条目（id `dsh-develop-ui.cmd-whitelist`），selector 匹配「存在 pending approval 且为 shell 命令类」时接管 composer 区域：

- **白名单命中**：组件 effect 中代答 `allowed-once`，正常渲染默认输入区（回落方式见 §4 spike 项）。
- **未命中**：渲染自定义三键审批面板（拒绝 / 允许一次 / 永远允许）。
- **不匹配**：selector 落选，链回落默认 InputBar，官方面板逻辑不受影响。

全程**不触碰 host 半**、不新增 RPC 路由；白名单纯 client 侧 localStorage。

## 2. 模块划分

| 模块 | 文件 | 职责 |
|------|------|------|
| 白名单 store | `src/client/approval/cmdWhitelist.ts` | 增删查、持久化（localStorage）、normalize + match 纯函数 |
| chain 条目 | `src/client/approval/WhitelistEntry.tsx` | selector + 接管组件：命中自动代答 / 未命中挂面板 |
| 审批面板 | `src/client/approval/ApprovalPanel.tsx` | 三键 UI：展示命令全文、tool 名、reason；按钮接线 |
| 管理浮层 | `src/client/approval/WhitelistManager.tsx` | 列表 / 删除 / 手动添加 / 模式切换 |
| 入口接线 | `src/client/index.ts`、`src/client/shell/DevFrame.tsx` | 注册 chain 条目；底部菜单栏 ⚙ 入口 |

## 3. 关键机制

### 3.1 命令提取

复刻官方 `commandOf` 语义（该函数未从包入口导出，需自实现约 10 行）：

1. selector 拿到 `ComposerChainProps.interactions`，取 `kind === 'approval'` 的 `PendingWait`；
2. 用 payload.`callId` 经 `useSession`（conversation runtime）查配对 `RunningToolCall`；
3. bash 族 tool 的 `args.command` 即命令行；取不到 → selector 不命中（交给官方）。

### 3.2 应答

`PendingApproval.answer(outcome)` 是包内领域封装，构造参数仅需 carrier（`PendingWait<'approval'>`）。**若 `PendingApproval` 无法从包入口/深导入拿到**（导出面未含，见 spike），则直接调 carrier `respond()`，result 编码照抄官方 `ApprovalPanel` 实现（读包内 client.js 对应分支）。三键面板同样路径。

> 「永远允许」的实现 = 白名单写入 + `answer('allowed-once')`，线上无第三种结局。

### 3.3 白名单数据

```ts
interface WhitelistEntry {
  id: string;          // randomUUID
  tokens: string[];    // normalize 后保留的前 N 个 token（N = tokenCount）
  tokenCount: number;  // 粒度：1 = 命令名；2..总数-1 = 子命令前缀；= 全部 = 整行精确（配 exact）
  exact: boolean;      // 整行精确：目标 token 数必须与 tokenCount 相同（不命中带多余参数的命令）
  createdAt: number;
}
```

> 实现修订（2026-08-31）：整行精确档需 `exact` 标记——纯前缀语义下「全部 token」条目会命中带多余参数的命令变体（如 `mvn clean package -D x extra`），与用户对"精确"的直觉冲突，故追加布尔字段区分。

- localStorage key：`dsh-develop-ui.cmdWhitelist`（JSON 数组；读入做结构校验，坏数据回退空表）。
- normalize：trim + 连续空白折叠为单空格 → split 成 tokens（命令两侧语义不变的前提下）。
- match（统一前缀语义）：目标命令 normalize 后取 tokens，与条目 `tokens` 逐 token 比较——**目标前 N 个 token 与条目完全相等即命中**（N = entry.tokenCount）。整行精确 = N 恰为目标 token 总数，天然被前缀规则覆盖；token 边界对齐，`mvn` 不命中 `mvnx`，`mvn clean package` 不命中 `mvn clean install`。大小写敏感；Windows 下 cmd 内建命令不区分大小写的问题 MVP 不处理，文档标注。
- store 形态：参照 `termStore`/`fileStore` 的轻量订阅模式（`getSnapshot/subscribe`），便于面板与管理浮层同实例。

### 3.4 「永远允许」粒度候选

审批面板「永远允许 ▾」展开时，按当前命令 tokens 自动生成候选列表：

| 候选 | token 数 | 示例（`mvn clean package -D maven.test.skip=true`） |
|------|----------|-----------------------------------------------------|
| 命令名 | 1 | `mvn` |
| 子命令前缀 | 2..总数-1（下拉可调） | `mvn clean` / `mvn clean package` … |
| 整行精确 | 全部 | `mvn clean package -D maven.test.skip=true` |

- 候选默认选中「子命令前缀中 token 数 = 命令主体」档或「整行精确」？——**默认选整行精确**（风险最低）；命令名/子命令前缀档以警示色标注「可匹配更多命令，含任意参数」。
- 管理浮层手动添加同理：输入命令 + 选择粒度（命令名 / 子命令前缀 token 数 / 整行）。

### 3.5 管理浮层

底部通用菜单栏新增 ⚙ 按钮 → 浮层（fixed 居中卡片，仿 WorkbenchEditor 授权面板样式）：条目列表（tokens 展示 + 粒度标签 + 删除）、手动添加输入框（命令 + 粒度选择：命令名 / 子命令前缀 token 数 / 整行）、清空全部。

## 4. 待 spike 验证项（实施前必须先验证）

| # | 问题 | 验证方式 | 不成立的备选 |
|---|------|----------|--------------|
| S-1 | chain 条目注册参数（selector 签名/返回约定）与**匹配优先级**：插件条目 vs 官方 ApprovalPanel 条目同命中时谁生效 | 读 cordis slots 运行时 + conversation `apply` 装配代码；最小条目真机打印 | 若官方条目优先且不可让位 → 方案改为「面板增强」不可行时，退而求其次：不做接管，仅做"代答后官方面板自动消失"不可行则本功能阻塞，需联系 DSH 官方开 hook |
| S-2 | 代答完成后如何回落默认输入区：selector 命中后组件 render null 是否继续链 / 是否有 fallback 组件可渲染 | 同上 | 备选：组件内自渲染最小输入占位（体验降级）；或 effect 代答后强制自身 selector 重算落选 |
| S-3 | `PendingApproval` 可导入性（入口导出或深路径稳定）与 `respond()` result 线上编码 | 查包 exports；必要时读 client.js `answer` 分支照抄编码 | 无（总能落到 respond 直调） |
| S-4 | chain 条目组件内 `useSession` 可用性（取 RunningToolCall 的通道） | 真机最小用例 | 备选：从 payload 字段降级展示（无命令行则面板仅显示 toolName/reason） |

### W0 spike 结论（2026-08-31 回写）

| # | 结论 | 依据 |
|---|------|------|
| S-1 | **可行**：`conversation.composer` 为 chain 槽（scope session），条目注册需 `select`（纯函数）+ `priority`；链按 priority **升序**评估（默认 0，同值按注册序）。官方 ApprovalPanel 条目 `select: interactions.find(i => i.kind === 'approval') ?? null`、`priority: 1`。**插件条目 priority 0（默认）→ 先于官方评估**；selector 命中（approval 且配对 tool call 含 command）→ 插件接管；不命中 → 官方条目接管，天然共存 | ui-slots `index.d.ts` ChainSelect/ChainRenderOpts + client.js `selectApproval`/注册段 |
| S-2 | **可行（无需回落占位）**：`conversation.composer` chain 使用 `overlay: true`——接管时默认 InputBar **display:none 隐藏而非卸载**（DOM/草稿存活）；代答后 `approval/resolved` 广播移除 pending → 插件 selector 自然落选 → InputBar 自动恢复。组件命中白名单时 effect 代答 + 渲染空即可 | ui-slots ChainRenderOpts.overlay 注释（唯一消费者 = conversation.composer） |
| S-3 | **需自建等价封装**：包入口未导出 `PendingApproval`/`commandOf`/`ApprovalPanel`（`./src/*` 指向的 src 未随包发布）。`PendingWait` 自 `@deepseek-ai/dsh-client-runtime/client` 导出（payload/respond）；应答编码照抄 client.js：`wait.respond({ ok: true, value: { sessionId: wait.sessionId, approvalId: wait.payload.approvalId, outcome } })`，`receipt.accepted === false` 时抛错。`commandOf` 照抄：`JSON.parse(call.argsRaw).command`（仅 string 返回）。`conversationContextKey` 自 runtime 导出。`ApprovalResponsePayload` 经 `dsh-client-connection/client` re-export | client.js PendingApproval.answer 段 + runtime/connection d.ts |
| S-4 | **可用**：官方 ApprovalPanel 同款——组件内 `props.useSession(snapshot => …)` 查配对 tool call；且 `ComposerChainProps.session` 属 owner props，**selector 内可纯函数使用**（官方要求 decline 决策必须在 selector，组件内 render null 不会回退到下一条目）。`rootToolCall` 语义：`snapshot.chat.nodes.get(conversationContextKey('tool-call', callId))?.data.root` | client.js ApprovalPanel 段 + ui-slots ChainSelect 注释 |

**选型落地**：selector = shell 命令类判定（approval 存在 + 配对 call 的 `command` 可提取）→ 命中返回 carrier；非 shell → null 交官方。永远允许粒度候选由 `cmdWhitelist.buildCandidates(tokens)` 纯函数生成（tokenCount 1..N）。

## 5. 安全与边界

- 白名单**只**作用于 shell 命令类 approval；文件写入等其他审批不受影响。
- `npm run <script>` / `npx`、`mvn clean package` 等可间接执行任意代码——命令名/子命令前缀粒度在面板与管理浮层均以警示色标签标注；「永远允许」候选默认选整行精确。
- 代答走的仍是官方 `respond` 通道，host 审计、会话消息流完整保留（用户可在消息流看到命令已执行）。
- 会话断线期间 approval 由 runtime 清理（`handleDisconnected` 清 pending），插件无额外状态残留；白名单为纯本地数据无泄漏面。
