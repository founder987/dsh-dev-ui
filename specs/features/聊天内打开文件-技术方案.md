# 聊天内打开文件 · 技术方案

> 依据：`specs/features/聊天内打开文件.md` v2.0 ｜ 文档版本：v1.0 ｜ 状态：实施中

## 1. 总体设计

拦截 `ctx.workspaces.openPath`（实例方法 shadow）：DSH 全量唯一调用者即聊天文件打开
（conversation chat 条目 inject 的 `openFile` 回调，被 ProducedFiles chip 与
chatFileMentions mention 共用），包装后两个消费方同时生效，且不影响其他插件。

```
openPath(path)【绝对路径】
  → host stat 路由（新增）判定
    → 文件 + 工作区内 → filetree.openFile(path) + setPanelOpen(true) + setReveal(path)
    → 否则 → 原方法（api.host.openPath 系统打开）
```

## 2. 模块划分

| 模块 | 文件 | 职责 |
|------|------|------|
| host stat 路由 | `src/host/index.ts` | `GET /api/dsh-develop-ui/fs/stat?path=` → `fs-service.stat`（已有）→ `{ version, type, size }`；错误带码（FS_NOT_FOUND 等） |
| 决策纯函数 | `src/client/fileopen/decide.ts` | `decideOpenPath(info, path, cwd)`：文件 + 工作区内 → `'dsh'`；否则 `'system'`；路径规范化（反斜杠→斜杠、去尾斜杠） |
| 拦截器 | `src/client/fileopen/interceptor.ts` | `installOpenPathInterceptor(workspaces, deps)`：保存原方法 → 实例 shadow → 返回 restore；模块级防重复包装标志 |
| 接线 | `src/client/index.ts` | `inject` 增 `'workspaces'`；`ctx.effect` 安装拦截器（dispose 恢复） |

## 3. 关键机制

### 3.1 stat 判定

- `type === 'file'` 才走 DSH；`directory`（含「打开所在文件夹」→ `.` 解析为 cwd 目录）回落系统
- stat 失败（工作区外/不存在）→ 回落系统，不打断原 `.catch(() => {})` 语义

### 3.2 工作区判定

- cwd 取 `sessions.list.getSnapshot().byId[currentSessionId]?.cwd`（conversation 同款）；
  current 取 `sessions.list.getSnapshot().current`
- 规范化：`path` 与 `cwd` 均 `replaceAll('\\', '/')` + 去尾 `/`；命中 = `path === cwd || path.startsWith(cwd + '/')`
- cwd 缺失 → 回落系统（保守）

### 3.3 DSH 打开

复用文件树面板：`setPanelOpen(true)` + `openFile(path)`（内部按扩展名走图片预览）+ `setReveal(path)`（树中定位）。`openFile` 失败内部 setError 展示，不抛错。

### 3.4 拦截器生命周期

```ts
installOpenPathInterceptor(workspaces, deps): { restore(): void }
```
- 包装：`workspaces.openPath = (path) => decide(...) === 'dsh' ? dshOpen(path) : original(path)`
- 防重复：模块级 `Symbol` 标志（重复调用直接返回 noop restore）
- 原方法引用保存于闭包（`bind(workspaces)` 防 this 丢失）；restore 恢复原方法

## 4. 测试

| 层 | 内容 |
|----|------|
| 单测（decide） | 文件+工作区内→dsh；目录→system；工作区外→system；stat 失败→system；路径规范化（反斜杠/尾斜杠/大小写）；无 cwd→system |
| 单测（interceptor） | 包装调用分流（dsh/system 各走一路）；防重复包装；restore 恢复原方法 |
| host | stat 路由 200/404/错误码（fs-service.stat 已有实现，补路由级冒烟） |
| 真机 | 验收标准 7 项 |

## 5. 安全与边界

- 拦截面单一：全 DSH 仅 conversation openFile 调 openPath；sidebar 无调用，不受影响
- 白名单外行为不变：目录/工作区外/失败一律回落系统打开
- host stat 路由沿用 `isLocalRequest` 本机端口校验
