## 1. 总体设计

三段式流水线：**规划会话驱动**（借 DSH 自身模型能力识别意图与生成内容）→ **结构化协议解析**（严格 JSON 契约，而非自由文本）→ **HTML 渲染与落盘**（host 半确定性工程）。

```
┌─ client 半（闭包环境）──────────────────────────────────────────────┐
│  PlannerPanel（浮层容器，E1 底部菜单栏 🎯 入口）                      │
│    步骤① 说目标 → 步骤② 答问题 → 步骤③ 拿规划包                      │
│                                                                     │
│  plannerStore    localStorage：目标 / 画像 / 历史 / 进度（真源）       │
│  planSession     规划会话驱动（新增核心）                             │
│    ├ ① 建会话  SessionRuntime.create({cwd}) → open(id)               │
│    ├ ② 拿动作  经 conversation.input.left 槽标准 props 的             │
│    │            inputActions.setDraft(prompt) + submit()            │
│    └ ③ 读回复  订阅会话快照 chat.nodes → contentToText 提取           │
│  planParser      纯函数：fenced JSON → PlanDocument / IntentResult    │
│  promptBuilder   纯函数：画像 + 资料池摘要 → 三段式 prompt             │
│  poolStore       资料池缓存（同 plannerStore 模式）                    │
└─────────────────────────────┬───────────────────────────────────────┘
                              │ 同源 fetch  /api/dsh-develop-ui/*
┌─────────────────────────────▼─ host 半（Node）──────────────────────┐
│  plan/render    PlanDocument → 自包含 HTML（内联样式，零外链）         │
│  plan/save      ctx.fs 写盘（index.html / plan.json / plan.md）       │
│  learn/github   GitHub Search API 拉取 + 内存缓存 + 限流识别          │
│  learn/feeds    多源 RSS/JSON 聚合，逐源独立降级                       │
│  system/open    系统浏览器打开规划包（已有，直接复用）                  │
└─────────────────────────────────────────────────────────────────────┘
```

**设计取舍说明**

| 取舍 | 选择 | 理由 |
|------|------|------|
| 谁做"智能" | DSH 自身模型（新建规划会话） | 零 API Key、零模型接入成本；DSH 模型能力现成 |
| 是否复用当前会话 | 否，新建专用会话 | 不污染开发对话；用完即弃，可重复生成 |
| 模型输出形态 | 严格 fenced JSON | 自由文本无法可靠渲染成结构化 HTML |
| 资料链接来源 | 优先注入资料池，禁止编造 | 模型编造链接是本类功能的头号失败模式（E4） |
| HTML 打开方式 | 系统默认浏览器（主） + DSH 内预览（次） | DSH 预览 iframe 为 `sandbox="allow-scripts"`，外链跳转受限（见 §6.6） |

## 5. host 路由设计

全部挂 `/api/dsh-develop-ui/*`，**每个路由首行 `isLocalRequest(req, expectedPort)` 校验**（沿用现有模式）；写操作为 POST。

| 接口 | 方法 | 说明 | 请求 | 响应 | 新增 |
|------|------|------|------|------|------|
| `/plan/render` | POST | `PlanDocument` + 进度 → 自包含 HTML | `PlanRenderArgs` | `PlanRenderResult` | 是 |

| `/learn/github` | GET | GitHub 高分项目检索 | `?query&topic&sort&page` | `PoolResult<PoolRepo>` | 是 |

### 5.1 `/plan/save` 关键实现约束

现有 `fs-service.writeText` 只支持 `{kind:'replaceIfVersion'}`（见 F-6 与 `src/host/fs-service.ts` L81-102）。**需扩展写入意图**：

```ts
/**
 * 写入文本（扩展写入意图）。
 * @param intent - 'create' 要求目标不存在（FS_NOT_OBSERVED 视为冲突）；
 *                 'overwrite' 无条件覆盖；默认 'replace' 走版本守卫
 */
export async function writeTextV2(
  fs: FileSystem,
  path: string,
  content: string,
  intent: 'create' | 'overwrite' | { replace: string },
  sandboxRoot?: string,
): Promise<FsWriteTextResult>
```

- `'create'` → `{ kind: 'createIfAbsent' }`；已存在报错映射为 `PLAN_TARGET_EXISTS`（409），client 据此弹「覆盖 / 另存为新版本」
- `'overwrite'` → 省略 `expected`（无条件 create-or-overwrite）
- 路径边界：写入前 `path` 经 `ctx.fs.resolve()`，并 `ctx.fs.contains(cwdTarget, target)` 检查，越界拒绝（开发规范 §6.3）

## 6. 核心流程

### 6.1 规划会话驱动（E2 核心链路）

```
① 建会话
   sessionId = await ctx.sessions.create({ cwd: sessionCwd })
   ctx.sessions.open(sessionId)
   记录原 current，用于完成后切回

② 提交 prompt
   驱动器 DriverProbe 挂在 conversation.input.left（scope session）
   → 该槽组件随会话物化拿到标准 props 的 inputActions
   → effect 中判据：sessions.list.current === pendingSubmission.sessionId
   → 命中：inputActions.setDraft(prompt)
          inputActions.submit()
   防重：提交后立即从 plannerStore 清除 pendingSubmission

③ 读回复
   订阅 sessions.manager.sessions.get(sessionId)
   等到 running 由 true 回到 false（或 turn/end）
   → 取该轮之后最后一个可见 assistant 节点
   → contentToText 提取纯文本（复用 askFeed 的 ContentBlock 拼接逻辑）
   → planParser.extractFencedJson(text)
```

**触发纪律**

- 提交动作放在 `useEffect` 且以 `sentFlag` 守卫，避免 React 严格模式/重渲染导致重复提交
- 驱动器组件渲染返回 `null`（0 宽锚点），不影响 composer 布局（对齐 `HistoryRecall` 先例）
- 除步骤①②③外，**不再向该会话追加任何消息**；每轮 prompt 自包含（不依赖上下文记忆），保证可重放

**超时与取消**

| 阶段 | 超时 | 行为 |
|------|------|------|
| 意图识别 | 120s | 超时 → 提示「模型响应超时」+ 重试按钮 + 「改用当前会话」降级入口 |
| 生成规划包 | 300s（S-4 验证后调整） | 超时 → 保留已收到内容，提供「仍在生成，稍后手动解析」按钮 |

**降级路径（S-1 不成立时）**

生成 prompt 后展示「复制 prompt」按钮 + 「打开对话」提示，由用户手动粘贴发送；回复后回到浮层点「解析我的回复」（用户粘贴回复文本）。功能完整，仅多一步手工。

### 6.2 结构化输出协议

prompt 强制模型**只输出一个 ```json 代码块**，schema 直接采用 §4.1 的 `IntentResult` / `PlanDocument`。

**解析（`planParser.ts`，纯函数，可单测）**

```
extractFencedJson(text):
  1. 优先匹配 ```json ... ``` 围栏（取最后一个，避免示例干扰）
  2. 回退匹配任意 ``` ... ``` 围栏
  3. 回退：首尾花括号切片
  → JSON.parse，失败返回 { ok: false, reason }
```

**结构校验（`validatePlanDocument`）**

- 必填字段与类型逐项校验（`stages` 数组非空、`resources[].url` 为 http(s)、`difficulty` ∈ 1..5）
- **URL 白名单校验（E4 关键）**：`origin === 'pool'` 的条目，其 `url` 必须命中本次注入的池条目集合；未命中则**自动降级为 `origin: 'model'`** 并在卡片上标注「模型补充，建议自行核实」
- 校验失败细分：`PLAN_JSON_INVALID`（语法）/ `PLAN_SCHEMA_INVALID`（结构）

**重试**

解析失败 → 发 `buildRepairPrompt(rawText, reason)` 一次；仍失败 → 展示「原文 + 重试」，并允许把原文按 markdown 直接渲染成简化版规划包（降级可用）。

### 6.3 资料池注入（防编造链接）

生成 prompt 中嵌入两段资料池摘要（纯文本，紧凑格式，控制 token）：

```
【可选项目池】（只允许从中选取 url，不得编造）
1. langchain-ai/langchain | ★98k | Python | LLM 应用框架 | https://github.com/langchain-ai/langchain
2. ...

【可选资料池】
1. [doc] OpenAI Cookbook - RAG 实践 | doc | 难度3 | 60min | https://cookbook.openai.com/...
2. [video] 3Blue1Brown - 神经网络 | video | 难度2 | 25min | https://...
```

- 池摘要由 `promptBuilder` 从 `poolStore` 按目标关键词/分类筛选（上限：项目 40 条、资料 60 条），避免超长
- prompt 明确要求：**优先选池内条目**；确实不足时可补充，但标注 `origin: 'model'`
- 池为空（首次使用、断网）时：prompt 中标注「本次无资料池，请给出你确知的权威来源，并全部标记为 model 补充」

### 6.4 HTML 生成（`src/host/plan-html.ts`）

`renderPlanHtml(plan, progress): string` — 字符串模板产出**自包含单文件**：

| 区块 | 渲染要点 |
|------|----------|
| `<head>` | `<meta charset="utf-8">` + `<meta name="viewport">` + 内联 `<style>`（暗色/亮色各一套，`prefers-color-scheme` 切换） |
| 目标与画像 | 目标原文、意图标签、`profile` 分层（已具备 / 待补齐）、补充信息 |
| 路线图 | `stages` 折叠卡片：阶段目标、周期、topics 复选、里程碑、`weeks` 汇总 |
| 资料区 | `PlanResource` 卡片：`<a href target="_blank" rel="noopener noreferrer">`；展示 kind 图标、难度星、`minutes`、`why`、`hint`；`origin==='model'` 加「模型补充」角标 |
| 实战项目 | `PlanProject` 卡片：名称、星标、`learn`、`hint`、仓库链接 |
| 意图专属区块 | `extras[].body` 经 `markdown-it` 渲染后内联 |
| 速查索引 | `index` 映射表 |
| 顶部提示 | 「在浏览器中打开可完整跳转；插件内预览时外链可能受限」+ 生成时间与版本号 |

- **零外链依赖**：不引 CDN/CSS/JS 资源，图片一律不内嵌外链（避免 CSP 拦截与断网空白）
- 正文中的用户/模型文本一律 HTML 转义（`escapeHtml`），防注入
- 难度星、图标用内联 SVG 或 Unicode 字符，避免外部资源
- 进度 checkbox：渲染时按 `progress.done` 置 `checked`；页面内勾选为本地便利行为（不保证持久化），真源在插件侧（§6.7）

### 6.5 落盘（E5，含 S-3 兜底）

**首选（目录结构，S-3 成立）**

```
<cwd>/规划/<目标名>/
├── index.html      # 自包含规划包（主产物）
├── plan.json       # PlanDocument（供重新渲染与迭代）
└── plan.md         # markdown 版（E6）
```

**兜底（S-3 不成立：writeText 不自动建父目录）**

| 备选 | 做法 | 评价 |
|------|------|------|
| A（默认兜底） | 平铺到 cwd 根：`规划-<目标名>-v<N>.html` / `.md` / `.json` | 零新能力，立即可用；缺点是文件散落 |
| B | 用插件自带终端通道执行 `mkdir`（`/terminal/create` + `/terminal/input`，cwd 为工作区） | 沙箱内可写，能保住目录结构；但引入 shell 依赖与异步时序 |

`PlanSaveResult.layout` 字段向 UI 透出实际形态，UI 据此展示对应路径与提示。**版本递增与备份**：同目标重新生成时 `version + 1`；目录结构下把旧 `index.html` 另存为 `index-v<N-1>.html`（平铺形态则由文件名版本号天然保留）。

`目标名` 安全化（client 侧 `planParser.ts` 的 `sanitizeTargetName` 纯函数）：去文件名非法字符 `\/:*?"<>|`、折叠空白、截断 40 字符、空则回落 `未命名目标`。

### 6.6 打开方式（"点击就能看视频/文档"的落地）

| 入口 | 行为 | 说明 |
|------|------|------|
| 浮层「在浏览器打开」按钮（主） | `POST /system/open { path: htmlPath, action: 'open' }` → `explorer.exe <path>` → 系统默认浏览器 | 浏览器中所有外链**完全可用**（含 `target="_blank"` 新标签） |
| 「在 DSH 中预览」按钮（次） | 复用 `filetree/openFile(htmlPath)`（C11 已有 iframe 预览） | iframe 为 `sandbox="allow-scripts"`（F-9），**外链跳转受限**；页面顶部已内置提示引导改用浏览器 |
| 文件树中点击该 html | 同上（DSH 内预览） | 无需额外实现 |

> 这是"资料必须能点开"这一硬要求的关键设计：**DSH 内预览不满足跳转需求，因此主入口指向系统浏览器。**

### 6.7 持久化与历史

| 数据 | 位置 | 说明 |
|------|------|------|
| 步骤状态、目标、意图、问答、画像 | `plannerStore` → localStorage `dsh-develop-ui.planner` | 关闭重开 DSH 后可继续 |
| 进度勾选（真源） | 同上，`PlanProgress.done` | 按目标隔离 |
| 历史规划列表 | 同上，`HistoryEntry[]`（目标、意图、版本、落盘路径、时间） | 「历史规划」区可再次打开或重新生成 |
| 资料池缓存 | `poolStore` → localStorage `dsh-develop-ui.pool`（含 `syncedAt`）、host 侧内存缓存 | host 内存缓存避免重复出网与限流 |
| 规划包内容 | 工作区文件（`plan.json` 为权威数据） | 换机器/重装插件后从文件恢复 |

数据损坏处理：读入做结构校验，坏数据回退为空并提示可重置（对齐 `cmdWhitelist` 的做法），不阻塞其他功能。

## 7. 权限与安全设计

| 项 | 措施 |
|----|------|
| 本机校验 | 所有 `plan/*`、`learn/*` 路由首行 `isLocalRequest(req, expectedPort)`，非本机 403 |
| 写入边界 | 写盘前 `ctx.fs.resolve()` + `ctx.fs.contains(cwd, target)`；越界拒绝（`PLAN_SAVE_DENIED`） |
| 沙箱兼容 | 写盘走 `ctx.fs`，携带会话 `workspace-write` 策略；被拒时给明确提示，**不绕过**（开发规范 §6.5） |
| 版本冲突 | `overwrite` 前先 stat 取版本再 `replaceIfVersion`；冲突报 `FS_STALE_VERSION` → UI 提示冲突，禁止静默覆盖（开发规范 §6.2） |
| 路径注入 | 目标名经 `sanitizeTargetName` 白名单化；host 侧 `spawnDetached` 传独立参数不拼命令串（沿用 C12 做法） |
| HTML 注入 | 规划包内所有动态文本 `escapeHtml`；不渲染模型给出的原始 HTML，只渲染 markdown 且经 `markdown-it` |
| prompt 注入 | 用户目标与回答直接进 prompt 属预期行为；资料池摘要为受控数据，不拼接未消毒的外部 HTML |
| 出网范围 | 仅 host 半出网（GitHub API + 配置的 RSS 源），域名硬编码白名单，不做任意 URL 代理 |
| 写操作语义 | 唯一的用户内容写路径是「生成规划包」，不触碰工作区既有文件（`createIfAbsent` 优先） |

## 8. 异常处理设计

### 8.1 新增错误码（`src/shared/errors.ts`）

```ts
// 规划域
PLAN_JSON_INVALID: 'PLAN_JSON_INVALID',       // 模型输出非法 JSON → 触发一次修复重试
PLAN_SCHEMA_INVALID: 'PLAN_SCHEMA_INVALID',   // JSON 合法但结构不符 → 触发一次修复重试
PLAN_TARGET_EXISTS: 'PLAN_TARGET_EXISTS',     // create 模式下目标已存在 → 409，UI 弹覆盖/另存
PLAN_SAVE_DENIED: 'PLAN_SAVE_DENIED',         // 路径越界 → 400
PLAN_RENDER_FAILED: 'PLAN_RENDER_FAILED',     // 渲染异常 → 500

// 会话驱动域
DRIVER_SESSION_UNAVAILABLE: 'DRIVER_SESSION_UNAVAILABLE', // 无 cwd / 建会话失败
DRIVER_SUBMIT_FAILED: 'DRIVER_SUBMIT_FAILED',             // setDraft/submit 不可用
DRIVER_TIMEOUT: 'DRIVER_TIMEOUT',                         // 等待回复超时

// 资料池域
LEARN_UPSTREAM_FAILED: 'LEARN_UPSTREAM_FAILED', // 上游不可达（逐源）
LEARN_RATE_LIMITED: 'LEARN_RATE_LIMITED',       // GitHub 限流（403 + rate limit 头）
```

### 8.2 异常矩阵

| 场景 | 错误码 / 判定 | 处理方式 |
|------|---------------|----------|
| 无会话或会话无 cwd | `DRIVER_SESSION_UNAVAILABLE` | 提示「请先打开一个工作区会话，或在设置中指定工作区」，附重试 |
| 建会话失败 | `DRIVER_SESSION_UNAVAILABLE` | 同上；并给「改用当前会话」降级入口 |
| `inputActions.submit` 不存在（S-1 不成立） | `DRIVER_SUBMIT_FAILED` | 自动切降级路径：复制 prompt 交用户手动发送 |
| 模型回复超时 | `DRIVER_TIMEOUT` | 保留已收内容；提供重试与「手动解析」 |
| 模型回复非 JSON | `PLAN_JSON_INVALID` | 自动修复重试 1 次；再失败→展示原文 + markdown 简化渲染 + 重试按钮 |
| JSON 结构不符 | `PLAN_SCHEMA_INVALID` | 同上；若仅个别字段缺失，尽力补齐（缺 `minutes` 置 0、缺 `difficulty` 置 3）并标注 |
| 池内 URL 未命中 | — | 该条自动降级 `origin: 'model'` 并加角标，不报错 |
| 目标已存在 | `PLAN_TARGET_EXISTS` | 409 → 弹「覆盖 / 另存为 v<N+1> / 取消」 |
| 写入越界 | `PLAN_SAVE_DENIED` | 提示路径非法；回落平铺到 cwd 根重试 |
| 沙箱拒绝写入 | `FS_SANDBOX_DENIED` | 明确提示；提供「信任此文件夹」或「复制 HTML 到剪贴板」兜底（需求文档边界条件） |
| 版本冲突 | `FS_STALE_VERSION` | 提示「规划包已被外部修改」，提供重新读取后覆盖 |
| 打开浏览器失败 | — | 兜底：`system/open action:'reveal'` 在资源管理器定位 + 展示完整路径可复制 |
| GitHub 限流 | `LEARN_RATE_LIMITED` | 用缓存渲染 + 显示「上次同步时间」与「设置 Token 提升配额」提示 |
| 部分资源源不可达 | `LEARN_UPSTREAM_FAILED`（逐源） | 失败源灰态标注原因，其余照常显示（需求文档边界条件） |
| 资料池缓存为空且断网 | — | 展示内置精选清单，提示「点刷新获取最新」 |
| 浮层关闭时仍在生成 | — | 生成不中断；完成后在底部菜单栏按钮上打点提示 |
| localStorage 损坏 | — | 结构校验失败 → 回退空态并提示可重置，不阻塞 |

| 风险 | 影响 | 应对 |
|------|------|------|
| 模型输出 JSON 不稳定 | 解析失败率高，体验差 | 结构校验 + 一次修复重试 + markdown 简化渲染兜底；S-4 验证后决定是否拆两次生成 |
| 生成耗时过长（数分钟） | 用户以为卡死 | 进度提示 + 可切走继续生成 + 完成打点；超时保留部分内容 |
| 模型编造链接 | 资料不可用，失去信任 | 池内 URL 白名单校验 + `origin` 角标可视区分 + 失效链接反馈入口 |
| 资料池出网受阻（国内网络） | 池为空，退化为纯模型输出 | 内置精选清单兜底 + 逐源降级 + prompt 标注「无池」模式 |
| DSH 内预览无法跳外链 | "点击就能看"的核心体验受损 | 主入口指向系统浏览器（§6.6）；页面内置提示 |
| `ctx.fs` 不支持建目录 | 落盘结构降级为平铺 | 已设计兜底（§6.5），`layout` 字段向 UI 透出 |
| 官方会话 API 版本漂移 | 驱动链路失效 | 驱动层全部走运行时守卫 + 静默降级 + console 诊断（对齐 askFeed 做法）；`inject` 失败即降级为手动路径 |
| 规划会话消耗配额 | 用户成本 | 每轮 prompt 自包含但不重复注入全池；池摘要按目标筛选并限量；步骤①②③共 2–3 次调用 |
