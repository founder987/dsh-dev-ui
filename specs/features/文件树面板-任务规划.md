### S1 沙箱保存授权流（扩展）

**背景**：保存工作区外文件报 `file access denied under workspace-write mode`。**白名单方案**（dsh-fs-sandbox rc.5+）：`SandboxedFileSystem.writeText` 第 5 参接受单次 `SandboxExecutionPolicy`，writableRoots = `policy.workspaceRoot` + tmp —— 把用户信任的文件夹作为本次调用的 workspaceRoot 传入，即按文件夹粒度放行（与命令白名单同语义），无需 `/permission` 开全部权限。旧运行时忽略该参则回退 /permission 重试流（客户端不绕过沙箱）。

| 编号 | 任务 | 产出 | 状态 |
|------|------|------|------|
| S1-1 | 保存结果信号 | saveFile 返回 `'saved'/'sandbox-denied'/'failed'`；识别 `FS_SANDBOX_DENIED` | ✅ |
| S1-2 | 信任目录持久化 | localStorage `dsh-develop-ui.trustedDirs`；trustDir/cancelSandboxApproval | ✅ |
| S1-3 | 授权面板 | WorkbenchEditor「保存需要授权」卡片；工作区外文件常驻 ⚠ 标记 | ✅ |
| S1-4 | 白名单直写 | client 已信任目录保存携带 `sandboxRoot`；host write-text 透传为单次策略（fs-service writeText 第 5 参，rc.7 类型未暴露故 cast） | ✅ |
| S1-5 | 旧运行时回退 | 白名单参数被忽略仍被拒 → 1.5s×40 重试 + /permission 引导 | ✅ |

### C5 终端面板（扩展 · v2 技术决策变更）

**需求（v2，用户变更）**：终端为**内嵌底部面板**——打开后默认在底部（sidebar 工作区列**独占从顶到底**，面板只占 sidebar 右侧区域）；支持**多个终端 tab**，关闭交互参考文件内容 Tab（✕ 右邻居激活、右键/⋯菜单 关闭当前/全部/左侧/右侧、最后 tab 关闭后面板隐藏）。

**形态决策（覆盖 v1 外置 OS 窗口方案）**：内嵌终端 = client 端 xterm.js 画布 + host 端 PTY 会话（node-pty 或等价）+ 双向流式通道。⚠️ 技术面大幅变化（原生模块打包、webServer 流式能力、沙箱对 PTY 的约束），**实现前需复审技术方案**（建议 `/feature-tech-design`）。

**安全约束**：shell 参数走 host 端硬编码白名单（powershell/pwsh/cmd/bash；~~wt~~ 是终端模拟器应用、无法嵌入 xterm，探针后移除——见 `docs/开发记录/C5-0-终端探针.md`）；cwd 经 `fs.resolve` + stat 校验（默认当前工作区路径）；路由与 write-text 同级（POST + `isLocalRequest`）。

### C8 三区最小化与底部工具栏还原（扩展 · 用户变更）

**需求（用户变更 2026-08-26）**：文件列表区、文件内容区、聊天区支持最小化和还原，最小化后收缩到底部通用工具栏（底部栏提供对应还原开关，激活态标识）。

**现状盘点**：

| 区域 | 现状 | 缺口 |
|------|------|------|
| 文件列表区（树列） | 已有 ✕ 最小化 + 底部栏 📁 开关（C3），0 宽保挂载 | 无（能力已齐） |
| 文件内容区（内容列） | 已有 ✕ 最小化（setEditorOpen(false)），0 宽保挂载 | **底部栏无还原开关**（仅能点击文件恢复） |

### C9 终端窗口按工作区隔离（扩展 · 用户变更）

**需求（用户变更 2026-08-26）**：终端窗口需根据工作区隔离——切换到不同工作区时，终端窗口展示内容需隔离（各自的工作区拥有各自的终端 tab/会话）。

**现状**：`termStore` 为模块级全局单例，tabs/activeId/shells/creating/createError 跨工作区共享；切换会话（session cwd 变化）后终端仍显示旧工作区会话。

**设计要点**：

- 工作区标识 = 终端 cwd（与 DevFrame `termCwd` 推导一致：session cwd → recentWorkspace path → localStorage 回退）；同 cwd 视为同一工作区。
- 数据模型：`workspaces: Record<cwd, TermWorkspaceState>`，其中 `TermWorkspaceState = { tabs, activeId, shells, lastShell, creating, createError }`；`panelOpen` / `height` / `lastShell` 保持全局（面板开关与高度记忆为布局偏好，对齐 treeOpen/editorOpen 全局语义）；`shells` 探测结果为机器级能力 → 全局。
- 切换工作区（cwd 变化）：TermPanel 投影到对应 workspace；**不 kill 远端会话、不停 read 循环**（PTY 保留，0 高/隐藏挂载语义扩展）；目标工作区无会话 → 空态（cwd 有效可 + 新建），不自动创建（避免切工作区即 spawn shell）。
- `setPanelOpen(true, cwd)` 的自动创建首个 tab 逻辑限定在「当前工作区无 tab 且 cwd 有效」时触发（现有行为仅在按钮点击时发生，切换工作区不触发）。
- API 兼容策略：`getTermState()` 返回含 workspaces 的全量 state（uSES getSnapshot 引用稳定），组件内按当前 cwd 投影；所有写操作签名携带 cwd 定位 workspace。

| C9-3 | DevFrame 接线 | `toggleTermPanel(termCwd)` / TermPanel `cwd` prop 不变（termCwd 已随会话变化）；核对无全局调用遗漏 | ✅ |

### C10 提问浮层复制能力（微调 · 用户变更）

**现状盘点**：展开/收起已由 C7-1 覆盖（`AskFloat.tsx`：超 2 行 line-clamp 折叠 + 「展开/收起」按钮 + 新提问复位折叠），本次**增量仅为复制能力**。

**变更分类**：微调（纯 client 前端 UI 增量，无 DB/无 host 路由；变更量 <<30% → 增量任务）。

**设计要点**：

- **复制内容**：当前展示的提问**完整全文**（`displayed`，不受折叠态影响；与滚动跟随定位到的提问一致）。

### C11 HTML 文件预览（扩展 · 用户变更）

**需求（用户变更）**：打开 `.html`/`.htm` 文件时支持「源码 ⇄ 预览」切换：预览在内容列内以沙箱 iframe 渲染页面效果。

**变更分类**：扩展（纯 client 前端增量；无 DB、无新 host 路由——预览内容复用 `read-text` 已加载文本，经 iframe `srcdoc` 客户端渲染）。变更量 ≪30% → 增量任务。

**设计要点**：

- **检测**：`\.html?$/i` → `TabState.isHtml`（html 仍保留 `isCode=true`，monaco 源码编辑与 shiki 高亮路径不变）。
- **视图模式**：复用现有 `viewMode: 'preview'`（每标签独立记忆，md 与 html 互斥，无需新模式）；打开默认仍为 `source`。
- **渲染**：`<iframe sandbox="allow-scripts" srcdoc={previewHtml}>`——不授 `allow-same-origin`（脚本以不透明源运行，无法触达父页存储/网络凭证）与 `allow-top-navigation`（防跳出父页）；容器白底（#fff）；样式类 `.dskDevHtmlPreview`（对齐 `.dskDevMdPreview` 模式）。
- **刷新语义（对齐 md）**：预览渲染「最近一次保存/加载的内容」——`TabState` 增 `previewHtml` 快照：openFile/reloadFile 时写入初始内容，saveFile 成功后写入 `tab.content`；iframe srcdoc 变化即自动重载。**不做**编辑实时预览（防抖重渲染留后续迭代）。
- **边界（v1 声明）**：`srcdoc` 基址为 `about:srcdoc`，相对资源（`./style.css`、`<img src>`、同源 fetch）不可用；绝对 URL（https://…）资源可用。相对资源支持需 host 静态路由，本轮不做。
- **安全**：iframe 内脚本在沙箱内运行，不能读写父页 DOM/存储；表单提交被 sandbox 默认拦截（未授 allow-forms）；链接点击仅在 iframe 内导航。

## 5. 部署链路（每轮必走）

```
npm run build → pnpm pack →
rm -rf C:\Users\User\.dsh\profiles\desktop\node_modules\dsh-develop-ui →
pnpm -C "C:\Users\User\.dsh\profiles\desktop" install →
grep 标记验证安装副本 → 用户重启 DSH Desktop
```

> 同版本 file: tgz 必须先删 node_modules 目录，否则 pnpm 跳过（硬链）。
> 部署后验证 node-pty 完整（存在 `node_modules/node-pty/package.json`）——DSH 启动时的自安装若被中断会把 node-pty 落成只剩 prebuilds 的残缺态，而 pnpm 状态仍显示 up to date 不自动修复；届时从项目 `node_modules/node-pty` 整目录拷贝补齐（同版本 1.2.0-beta.15，prebuilds/win32-x64 即运行时绑定）。
