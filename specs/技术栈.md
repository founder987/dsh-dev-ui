# 技术栈选型：dsh-develop-ui

> DeepSeek Harness 客户端插件 ｜ 基于对 DSH 2.0.1（`dsh-plugin-desktop`）实际代码的查证
> 文档版本：v1.3 ｜ 状态：MVP 落地完成，RPC 通道最终修正

## 项目约束分析

- **项目类型**：DSH Desktop（Electron）内的 **Cordis 客户端插件（client plugin）**，非独立应用
- **用户量级**：个人自用（1 用户），代码质量按可发布标准
- **关键要求**：与 DSH 视觉一致；文件读写受沙箱/权限约束；md 源码/预览切换；三栏可最小化布局；对话可引用文件
- **部署环境**：随 DSH Desktop 运行，经 community market / profile bundles 安装，不重建桌面壳
- **平台**：Windows（开发），DSH 插件理论跨平台

## 核心架构决策：dual-half 插件模型（DSH 标准形态）

查证结论（来自 `dsh-cordis-client-runner`、`dsh-client-*` 实际代码）：

1. **DSH 官方 client 插件是"双半"包**：`exports["."]` 是 host 半（Node 侧），`exports["./client"]` 是浏览器半，`package.json` 顶层 `dsh.client.inject` 声明浏览器半的依赖注入图。
2. **浏览器半是受限闭包环境**：`React` 以闭包符号直接可用；**不能 `import` 任意 npm 包**；`fetch`、`require`、`setTimeout` 被拦截（网络/定时器归 host 半，需 `inject: ['timer']`）；能力通道只有 **ctx 注入服务**、**`host.call(method, args)`**、**`styles.insert`**。
3. **host 半无此限制**：可正常 import 任意 npm 包，可注册 `harness.handle(method, fn)` 供浏览器半调用。

**结论**：所有重逻辑（文件 IO、md 渲染、代码高亮）放 **host 半**，浏览器半只做 React UI 并通过 `host.call` 取数。这既是 DSH 官方模型，也天然满足"保存受沙箱约束"的安全要求。

## 推荐技术方案

### 前端（浏览器半 / client half）

| 层面 | 推荐方案 | 备选方案 | 选择理由 |
|------|----------|----------|----------|
| 框架 | React 18.3.x（DSH 生态强制） | 无 | `dsh-client-web-react` 提供 createSlotRenderer/SessionProvider/useInvoke；React 是闭包符号 |
| UI 组件 | `@deepseek-ai/dsh-client-ui-primitives` + `dsh-client-ui-theme` | antd | 与 DSH 视觉完全一致，避免引入第三方主题冲突 |
| 布局 | 复用 `ctx.layout` AppFrame（sidebar\|center\|details 三列）：文件树 → sidebar 面板、文件内容 → details 列（`ctx.layout` 开关/拖宽）、对话 = center 官方 UI | 接管 root 槽自绘（shadows-shipped-ui，重） | M0 验证：AppFrame 三列结构固定；方案 A 已确认（对话中置） |
| 面板入口 | 注册进 **sidebar slot**（参照 `dsh-client-ui-deliverables`）+ `details` 槽注册文件内容 | root slot 自绘 | deliverables 是"侧边栏面板 + conversation 交互"的最接近参考 |
| 状态管理 | React Context + useReducer | zustand（仅静态注入包可用） | **浏览器半闭包不能 import zustand**，Context 零依赖 |
| 编辑器 | 原生 textarea + 受控组件（MVP） | CodeMirror 6 / Monaco（需静态注入桌面壳，复杂） | 闭包约束下 textarea 是唯一零集成方案；编辑=纯文本，高亮交给预览 |
| md 预览 | host 半渲染 HTML → `dangerouslySetInnerHTML` | 静态注入 react-markdown | 浏览器半不能 import react-markdown，host 渲染是正解 |

### 后端（host 半 / host half）

| 层面 | 推荐方案 | 备选方案 | 选择理由 |
|------|----------|----------|----------|
| 语言 | TypeScript + ESM | 无 | DSH 全栈 TS，产物即 ESM |
| 文件系统 | `ctx.fs`（`@deepseek-ai/dsh-fs` 服务） | 自写 Node fs | 官方抽象：`resolve/stat/listDir/readText/writeText/editText`，**版本守卫原子写**，自动继承沙箱策略 |
| 工作区定位 | 当前会话工作区：client 半 `useSessions`（session cwd）+ `useWorkspaces`（recentWorkspaceId）自动检测 | 手动输入 | 免 host 路由，client 服务直达 |
| md 渲染 | `markdown-it` + `markdown-it-task-lists`（GFM 插件在 registry 不存在，任务列表替代） | remark/unified 系 | host 半可自由 import；同步、轻量、成熟 |
| 代码高亮 | `shiki`（已在 DSH 依赖树） | highlight.js | shiki 效果最佳且 DSH 运行时已携带 |
| RPC 通道 | host 半 **`ctx.webServer` HTTP 路由**（`/api/dsh-develop-ui/*`，本机端口校验），client 半 fetch | `@Remote`（typert） | **最终落地**（v1.3）：`@Remote` 的 client 通道（api-remotes TYPERT_REMOTE 表）为官方包静态编译，第三方运行时注册的服务无现成 client 通道；market 官方第三方模式即 webServer 路由 |

### 数据层

| 层面 | 推荐方案 | 理由 |
|------|----------|------|
| 数据库 | **无**（文件即数据） | 数据就是工作区文件本身 |
| 状态持久化 | `ctx.storage` / localStorage（布局状态、最近打开文件） | DSH 提供存储域服务，布局状态记忆直接落这里 |

### 构建与分发

| 层面 | 推荐方案 | 备选方案 | 选择理由 |
|------|----------|----------|----------|
| 包管理 | pnpm（DSH 内置 pnpm 11） | npm | 与 DSH 一致，锁文件可靠 |
| 构建 | **esbuild 双入口**：host→`lib/index.js`（ESM，依赖外部化）；client→`lib/client.js`（cjs + banner/footer 包装为 **`__ModuleLoader__.load({id, factory})` lazy-CJS**，react/`@deepseek-ai/*` external） | tsup / rolldown | M0 验证：esbuild 可产出官方同构格式（SMOKE PASS） |
| 类型 | `lib/types/*.d.ts` + `exports.types` | — | 对齐 DSH 包规范 |
| 分发/安装 | **profile bundle**：包内 `cordis.patch.yml`（`dsh.bundle.patch`）+ 安装后加入 profile `dsh.profile.bundles` | community market 安装 | M0 验证：market 安装强制校验 `dsh.bundle.patch` 存在 |
| 依赖版本 | 跟随 `0.1.0-rc.7`（当前 DSH 版本） | — | peerDeps 与运行时对齐，避免双 React 等冲突 |

## 技术依赖关系

```
dsh-develop-ui (dual-half Cordis plugin)
│
├── host 半  lib/index.js（Node，可自由 import）
│     ├── ctx.fs（@deepseek-ai/dsh-fs：listDir/readText/writeText/editText，版本守卫）
│     ├── markdown-it + markdown-it-gfm ──→ md → HTML
│     ├── shiki ──→ 代码高亮（注入 HTML）
│     └── harness.handle('fs.*' | 'md.render' | ...)  ← RPC 服务端
│
└── client 半  lib/client.js（__ModuleLoader__ lazy-CJS，require react/@deepseek-ai/*）
      ├── ctx.layout AppFrame ──→ 三列（sidebar | center 对话 | details 文件内容）
      ├── ctx（inject: primitives/theme/locale/workspace/conversation…）
      ├── 文件树组件（sidebar 面板，数据经 ctx.remote fsApi）
      ├── textarea 编辑器 + dirty 标记 + Ctrl+S（details 列，ctx.remote fsApi）
      ├── md 预览（ctx.remote mdApi → dangerouslySetInnerHTML）
      ├── conversation additive 插槽（@文件 引用：session.header.actions / input.dock）
      └── ctx.remote.<ns>.<method>  ← RPC 客户端（@Remote 服务）
```

## 已确认的决策（v1.1）

1. **对话窗口 → 复用官方 `dsh-client-ui-conversation`**：inject conversation 插件获得完整对话能力（Composer、聊天流、busy-Enter），三栏右栏嵌入其对话视图；参考 `dsh-client-ui-deliverables`（sidebar 面板 + conversation 交互的官方范例）。实现第一步先验证 conversation 组件嵌入自定义面板的可行性，若受限再评估自建。
2. **编辑器 → textarea MVP**：浏览器半闭包约束下的零集成方案；编辑态为纯文本受控组件，语法高亮交给预览模式（md 走 host 渲染，代码文件暂不高亮）。编辑体验（行号/高亮）作为 P2 增强项，届时再评估 CodeMirror 静态注入。
3. **安装方式 → 动态安装**：社区插件标准形态，经 community market / profile `dsh.profile.bundles` 动态加载；浏览器半遵守闭包约束（React 符号 + ctx 服务 + host.call），不依赖桌面壳重建。

### v1.2 修正（M0 技术验证后）

4. **布局 → 接受 DSH 原生三列（方案 A）**：AppFrame 三列结构固定（sidebar|center|details），中列固定为官方对话。最终编排：文件树 → sidebar 面板、文件内容 → details 列（`ctx.layout` 开关/拖宽）、对话 = center 官方 UI（见 `docs/开发记录/M0-技术验证.md`）。
5. **RPC 通道 → `@Remote` 服务 + `ctx.remote`**：`harness.handle`/`host.call` 仅适用模型驱动动态包（clientCode eval），本插件为 bundle 静态包，host 半注册 `@Remote`（typert）服务，client 半经 `ctx.remote.<ns>.<method>` 调用（client-runtime Session 已证实）。
6. **client 半构建 → `__ModuleLoader__` lazy-CJS**：esbuild `format:'cjs'` + banner/footer 包装，react/`@deepseek-ai/*` external（宿主模块表提供）。client 半可 `require("react")`/`require("@deepseek-ai/*")`，但不可 import 任意第三方 npm 包（md 渲染保持 host 半）。
7. **安装形态 → profile bundle**：包内 `cordis.patch.yml`（`dsh.bundle.patch`）+ 安装后加入 profile `dsh.profile.bundles`；market 安装强制校验 patch 存在。
