# 产品概述：dsk-develop-ui

> DeepSeek Harness 客户端插件（client plugin）
> 文档版本：v1.0 ｜ 状态：需求澄清完成

## 项目愿景

在 DSH 内获得"文件树 + 文件编辑/预览 + agent 对话"同屏协作的一体化开发视图，让日常 agent 开发不再切换外部编辑器。

## 核心价值主张

- **一体化开发视图**：文件浏览、查看/编辑、md 渲染预览、agent 对话集中在同一界面，像 VS Code 里嵌入 AI 面板的体验。
- **零切换**：80% 的文件查看/预览/编辑场景在插件内完成，替代"DSH 对话 + 外部编辑器"的来回切换。
- **对话感知文件**：对话中可引用文件，agent 明确知道用户指的是哪个文件，减少歧义。

## 目标用户

- **用户类型**：本人（DSH 上的 agent/插件开发者），后续可扩展给 DSH 社区同类开发者。
- **痛点**：开发/调试 agent 时，需要在文件、预览、对话之间频繁切换，上下文割裂、效率低。
- **使用场景**：在 DSH 会话中开发插件或 agent，边看代码边与 agent 对话验证，边改边存。

## 界面布局（方案 C：接管 root 槽的五列同层级布局，M1 落地）

官方 `ui-layout` 条目在 profile `cordis.patch.yml` 中禁用，本插件接替布局提供者角色（root 槽 DevFrame 五列框架 + `ctx.layout` 服务 + ThemePresenter）：

```
┌──────────┬──────────┬──────────────┬──────────────┬──────────┐
│ sidebar   │ 文件树列  │  文件内容列    │  聊天区       │ details  │
│ 会话列表   │ 路径输入  │  多标签编辑器  │ （官方会话）   │ 工具详情  │
│（官方）    │ 面包屑/树 │  高亮可编辑   │              │（官方）   │
│ 独占全高   ├──────────┴──────────────┴──────────────┴──────────┤
│           │ 终端面板（多 tab 内嵌终端，C5 v2）                    │
│           ├──────────────────────────────────────────────────┤
│           │ 底部通用菜单栏（📁 文件列表开关 + >_ 终端开关 + 预留）   │
└──────────┴──────────────────────────────────────────────────┘
```

> 布局决策（M1 定稿）：对话区置于右侧第 4 列，从左到右为 工作区(sidebar) → 文件树 → 文件内容 → 聊天区；details 在工具调用时于最右缘弹出。各列拖拽调宽（树 240–480、内容 480–1200，宽度 localStorage 记忆），文件树/文件内容可独立最小化（0 宽保挂载）。官方 sidebar/conversation/details 条目原位渲染，功能全保留。

## 系统核心板块

| 板块 | 功能范围 | 优先级 |
|------|----------|--------|
| 布局编排 | 方案 C：禁用官方 ui-layout，本插件提供 root 五列框架（sidebar/文件树/文件内容/conversation/details）+ `ctx.layout` 服务 + 主题呈现；列宽拖拽记忆、列独立最小化、底部通用菜单栏（文件列表开关 + 终端面板开关）+ 底部多 tab 终端面板 | P0 |
| 文件列表 | 文件树列展示工作区目录树（含子目录），点击文件在内容列打开，列可最小化，支持"在文件列表中定位" | P0 |
| 文件查看与预览 | 多标签打开；代码 shiki 高亮可编辑（暗色）；md 源码/渲染预览切换；图片预览 | P0 |
| 文件编辑与保存 | 支持编辑；修改后未保存标识亮起；Ctrl+S 保存落盘后标识消失；保存不弹确认框 | P0 |
| agent 对话窗口 | 复用官方 conversation（center 列）；支持引用文件（@文件），agent 能感知引用上下文 | P0 |

| 权限与安全 | 保存与 DSH 沙箱（workspace-write）对接：工作区外文件保存被拒时弹出"信任文件夹"授权，信任后引导会话 `/permission` 切完全访问，插件自动重试保存 | P1 |

## 验收标准

### MVP 验收（第一版可用的标准）

- [x] 文件树面板可折叠（📂 按钮 / ✕ 关闭），面板开关状态会话内保持，工作区路径 localStorage 记忆
  - ⚠️ 实现差异：文件内容在**面板内**展示（details 槽为官方工具详情，未替换；见 `docs/开发记录/MVP-验收核对.md`）
- [x] 文件列表正确展示**当前会话工作区**目录树（session cwd 自动检测），含子目录（懒加载展开），文件夹/文件图标可辨识，隐藏目录过滤
- [x] 点击任意文件可在面板查看内容；md 文件支持"源码 / 渲染预览"一键切换（预览含代码块高亮）
- [x] 编辑后出现 ● 未保存标识，Ctrl+S 保存成功后标识消失，内容写入工作区（版本守卫）
- [x] 对话中可用 @文件 引用文件（composer @文件 按钮 → 面板选文件 → 注入引用），agent 可识别（文本引用；片段级引用也已实现）
- [ ] 日常开发中 80% 的文件查看 / 预览 / 编辑场景在插件内完成（待日常使用验证）

### 完整版验收

- [ ] 连续使用 8 小时无崩溃、无内存明显膨胀
- [ ] 大文件（>1MB）与多文件切换流畅，无卡顿
- [x] 片段级引用（选中发送）可用且准确

## 非功能需求

- **性能**：文件列表加载、文件切换响应快（目标 <300ms 感知延迟）；大文件打开不卡死界面
- **稳定性**：长时间使用（8h+）无崩溃、无状态错乱
- **安全**：保存与 DSH 沙箱 / 权限体系兼容，不绕过既有权限策略

## 项目约束

- **技术**：基于 DSH 插件体系（Cordis client 插件 + 必要时的 host 端能力），复用现有工作区 / 权限机制，不另起炉灶
- **范围**：第一版聚焦 P0 板块，P1 能力在架构上预留接口
- **形态**：自用优先，代码质量与可维护性按可发布标准要求

## 风险与假设

- **假设**：DSH 现有 client UI 插槽（slots）与工作区服务足以承载三栏布局与文件读写；若不够，需要组合 host 端插件提供文件系统访问
- **风险**：编辑保存涉及文件写盘，受 DSH 权限 / 沙箱策略约束，保存链路可能需要权限确认或授权机制，可能影响"保存不弹确认框"的体验
- **风险**：@文件 引用需要与 agent 上下文 / 附件机制对接，若现有机制不支持需要自定义注入
- **风险**：与 DSH 自带工作区面板的功能重叠，需明确共存策略（替换 / 并存 / 增强）
