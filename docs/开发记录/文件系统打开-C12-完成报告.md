# 功能实现完成报告：文件系统打开（C12）

> 日期：2026-08-31 ｜ 状态：✅ 编码完成（C12-1~C12-3），真机验证待执行 ｜ 依据：`specs/features/文件树面板-任务规划.md` v1.12

## 背景

文件树面板（文件夹列表）行需要系统打开能力：① 在文件资源管理器中打开（定位文件）；② 系统默认应用打开（无默认应用时 Windows 弹「选择应用」）；③ 打开方式/配置默认应用。

## 关键设计

- **走 host 新路由，不经过 `workspaces.openPath`**：openPath 已被「聊天内打开文件」拦截器包装为 DSH 打开，文件树面板的系统打开需系统语义 → 新增 `POST /api/dsh-develop-ui/system/open`，天然隔离。
- **动作映射（Windows）**：`reveal` 文件 `explorer /select,<path>`（定位选中）/ 目录 `explorer <path>`；`open` `explorer <path>`（默认应用，无默认应用弹选择应用）；`choose-app` `rundll32 shell32.dll,OpenAs_RunDLL <path>`（强制打开方式对话框）。
- **安全**：`child_process.spawn` 无 shell（路径独立参数防注入）+ detached/unref；host resolve+stat 存在校验（删除路径 → FS_NOT_FOUND → 404）；`isLocalRequest` 守卫。
- **交互**：树行右键菜单（复用 `dskDevCtxMenu`），文件 3 项 / 目录 1 项，点外/Esc 关闭，失败 console.warn 静默。

## Bugfix（2026-08-31 真机反馈）

**现象**：目录无法在资源管理器中打开；文件行右键无反应。

**修复 1（确定性）**：`spawnDetached` 原依赖 `'spawn' 事件`（Node 15+）确认启动——旧运行时永不触发 → 路由 await 挂起 → 点击菜单项无任何反馈。改为**立即 resolve + unref**（explorer/rundll32 为 GUI 启动器，spawn 调用即返回），启动失败走 `error` 事件记录日志。

**修复 2（诊断）**：client 右键打开菜单、菜单项点击、fetch 结果、host spawn 调用均加 `[dsh-develop-ui]` 前缀日志——若右键仍无反应，控制台日志可区分「菜单未弹出」（无 row menu open 日志）vs「点击无效」（有 row menu open 但无 system open ok/失败详情）。

**验证**：typecheck/build/SMOKE/system-open 全绿；已重装 0.1.5。

**修复 3（2026-08-31 第二轮反馈：选中无状态 / explorer 不弹）**：
- **explorer 不弹（根因）**：文件树路径为 DSH 内部格式（正斜杠/混合分隔符 `C:/proj/src`），explorer.exe 不识别 → spawn 成功但无窗口。host `system/open` 路由改用 `ctx.fs.resolve` + `ctx.fs.processPath`（与 terminal 的 cwd 转换同通道）+ 分隔符归一为反斜杠后再 spawn。
- **选中无状态**：文件行 `data-active` 改为规范化比较（反斜杠→正斜杠统一，聊天打开路径与树路径格式不同）；目录行新增展开高亮（`data-active={expanded}`）。

**验证**：typecheck/build/SMOKE 全绿；已重装 0.1.5。
