## 7. 已知事项

- 首个构建目标：`pnpm build` 需 src 下已有源码（当前为骨架，构建脚本就绪）
- registry 已验证可达：typescript/esbuild/markdown-it/shiki/@deepseek-ai 均能解析
- **环境备注（Windows + DSH Desktop）**：
  - PATH 中 `pnpm` 为 DSH Desktop 内置包装器（经 Electron 运行）；`pnpm run` 会触发"运行前依赖检查"并嵌套 spawn 安装 → 已在 `.npmrc` 设置 `verify-deps-before-run=false`
  - npm/npx 的 .ps1 被 PowerShell 执行策略拦截 → 统一用 pnpm / node 直调
  - 沙箱内 esbuild 的 Node spawn（piped stdio）被文件沙箱按设计拦截（EPERM）→ 构建需在完整权限或真实终端执行
  - pnpm 11 生成 `pnpm-workspace.yaml`（allowBuilds），已批准 esbuild 构建脚本
- 修正：`package.json` exports 的 types 路径指向实际产物（`lib/types/host/index.d.ts`、`lib/types/client/index.d.ts`、`lib/types/shared/rpc.d.ts`）
