## V3 验证详情（通道与格式）

### 3.1 插件加载模型（查证结论）

DSH 第三方插件是 **profile bundle** 形态：

1. 安装 = profile dependency + `dsh.profile.bundles` 声明 + **包的 `dsh.bundle.patch`（cordis.patch.yml）必须存在**（market install 的 `assertInstalledBundleFromSnapshot` 强制校验）
2. 启动时 `dsh-app-boot` 读 profile bundles → 每个 bundle 的 patch 组合成加载层 → host 半 `lib/index.js` 执行
3. client 半经 `dsh-client-modules` 扫描：包的 `dsh.client` 声明（platform/inject/immediately）+ `exports["./client"]`（→ `lib/client.js`），经 `/plugins/<id>/client.js?rev=` 提供给浏览器

### 3.2 client bundle 格式（可执行验证 ✅）

官方 client 包（如 `dsh-client-ui-workspace`）的 `lib/client.js` 是：

```js
window.__ModuleLoader__.load({
  id: "@deepseek-ai/dsh-client-ui-workspace",
  factory: (require) => {
    var module = { exports: {} };
    var exports = module.exports;
    let react = require("react");           // 依赖从宿主模块表解析
    ...
    exports.apply = apply;                   // 导出 client 插件主体
    return module.exports;
  }
});
```

**本插件已改造实现**：`build.mjs` 用 esbuild `format: 'cjs'` + banner/footer 包装产出同构格式（react / `@deepseek-ai/*` external）。冒烟测试 `tests/integration/client-bundle-format.test.mjs` 通过：

```
[1] load called, id = dsk-develop-ui
[2] factory returned, exports keys = [ 'apply' ]
[3] apply() 可调用 ✅
SMOKE PASS
```

### 3.3 通信通道（修正 `specs/技术栈.md` 的认知）

| 通道 | 适用 | 结论 |
|------|------|------|
| `harness.handle` / `host.call` | **动态包**（模型驱动 `cordis_define`，client 半为 eval 源码闭包） | ❌ 不适用于本插件 |
| **`@Remote` 服务（typert）+ `ctx.remote.<ns>.<method>`** | **bundle 静态包** | ✅ **采用**：host 半注册 Remote 服务（如 `DynamicCordisRunner.getClientCode` 模式），client 半经 `ctx.remote` 调用（client-runtime Session 已证实） |
| HTTP 路由（host 注册 `/api/...`，client `fetch`） | 官方 market 模式 | 备选 |

### 3.4 client 半依赖能力（修正认知）

- ✅ 可 `require("react")`、`require("@deepseek-ai/dsh-client-ui-primitives")` 等（宿主模块表提供，**必须 external**）
- ✅ 可 `fetch` 同源 API、`setTimeout`（bundle 静态包无动态闭包限制）
- ❌ 不可 import 任意第三方 npm 包（react/`@deepseek-ai/*` 之外，除非打包进 bundle）→ **md 渲染保持 host 半**的设计不变

## V1 验证详情（布局）

### 4.1 AppFrame 事实（查证结论）

`dsh-client-ui-layout` 的 AppFrame 注册在 **root 槽**，固定三列：

| 列 | 宽度 | 内容槽 | 说明 |
|----|------|--------|------|
| sidebar | 56px rail 或 264–420px | `sidebar` 槽（`sidebar.workspaces` 会话浏览区） | 可折叠为 rail |
| center | 剩余 | `conversation` 槽（ConversationRoot 占据） | 对话主区 |
| details | 0 或 300–520px | `details` 槽（工具详情） | `ctx.layout` 开关、宽度拖拽 |

- 支持：sidebar 折叠、details 开关（`ctx.layout` panel transitions）、拖拽调宽、grid 状态
- **不支持**：自定义列数/列序/列内容归属

### 4.2 冲突点

产品三栏（工作区含文件列表 | 文件内容 | 对话）与 DSH 三列（会话侧栏 | 对话 | 详情）**结构不匹配**：DSH 中列固定为对话，产品要求中列为文件内容、对话在右。

### 4.3 可选方案（需产品决策）

- **方案 A（推荐）**：接受 DSH 三列 —— 文件树注册为 sidebar 面板（`sidebar` 槽 additive）、文件内容显示在 details 列（`ctx.layout` 打开）、对话 = center 官方 UI。开发量最小，V2 完全成立；代价是"对话中置、文件内容右置"。
- **方案 B**：对话保持 center；文件树 → sidebar；文件内容用 `shell.overlay` 浮动面板（可拖拽/全屏）。文件内容空间更大，但 overlay 与布局状态记忆需自建。
- **方案 C**：接管 root 槽自绘三栏（严格产品布局）。`replaceRisk: shadows-shipped-ui`，需自绘/嵌入会话列表、设置、主题等全部 shell 能力，且官方对话固定在 center 列无法右移——**需自建对话**，工作量最大。

## M1 补充验证：方案 C（接管 root 槽的布局提供者）

### slots 运行时契约（以 profile node_modules rc.7 运行时代码为准，勿信 dev 期 slots.d.ts 旧注释）

1. **single 槽同 cell 按 `priority` 升序选 winner**；同优先级重复注册**直接抛错**（`single slot "root" already has a registration at priority 0`）。「动态注册者赢」是过时注释，真机不存在。
2. **子槽声明全局唯一**：某条目声明过 sidebar 等子槽后，其存活期间任何人重复声明都抛 `slot "sidebar" is already declared (by an entry in "root" (x6))`。→ shadow root + 复用官方子槽座位**不可能**，唯一解是在 profile `cordis.patch.yml` 禁用官方 `ui-layout` 条目，由本插件接替。
3. `renderSlot` 绑定只允许渲染**本条目声明过**的子槽（SlotOwnershipError）。
4. 列表槽渲染按 `order` 升序（插件市场 community-market order 10，在 sidebar.footer.action）。

### 接替 ui-layout 必须提供的三件套

| 职责 | 实现 | 否则后果 |
|------|------|----------|
| `ctx.layout` 服务（toggleSidebar/openDetails/closeDetails） | `DevLayoutController`（index.ts）+ root 条目 store inject 钩子接线 | 官方 ui-sidebar / ui-conversation 调用即 throw |
| 主题呈现（body 暗色属性 + token 写 body + theme-color meta） | `ThemePresenter`（shell/theme.ts，复制官方逻辑） | 主题 token 不应用，界面无色 |
| root 槽五列框架（声明 sidebar/conversation/details/shell.overlay 子槽） | `DevFrame`（shell/DevFrame.tsx） | 官方条目无座位可坐 |

### 结论

- ✅ 方案 C 可行且已落地：五列同层级（sidebar | 文件树 | 文件内容 | 聊天区 | details），官方功能全保留
- ✅ client bundle 可 import `@deepseek-ai/dsh-client-ui-primitives`（宿主模块表内，图标直接复用）
- ⚠️ DSH 沙箱无文件夹级信任机制：可写根 = 会话工作区 + tmp，唯一授权通道为会话 `/permission` 切换权限模式；插件侧做「信任文件夹 + 引导切权限 + 自动重试保存」闭环（不绕过沙箱）
