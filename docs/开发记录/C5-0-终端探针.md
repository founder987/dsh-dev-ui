# C5-0 探针报告：终端 PTY 与流式通道

> 日期：2026-08-24 ｜ 阶段：C5 v2 终端面板 · 前置探针（任务规划 C5-0）
> 依据：对 DSH Desktop 2.0.1 运行时（`resources/app.asar.unpacked`）与 `@deepseek-ai/*` 宿主包的查证 + fetch 通道真机验证

## 结论总览

| 探针项 | 结论 | 证据 |
|--------|------|------|
| node-pty 在 host 半可用性 | ✅ **可行**：DSH Desktop 2.0.1 发行版**内置 node-pty@1.2.0-beta.15**，含 win32-x64 ConPTY 预构建；插件依赖同版本即可复用 N-API 预构建 | `app.asar.unpacked\node_modules\node-pty\prebuilds\win32-x64\conpty.node` |
| 原生模块 ABI 兼容性 | ✅ **已获官方实证**：DSH 自身在 Electron 运行时（CLI 经 `ELECTRON_RUN_AS_NODE=1` 拉起）加载该 node-pty 成功 → 同版本 node-pty 的预构建 ABI 与宿主兼容 | 发行版 node-pty 被 host 进程消费 |
| `ctx.webServer` 流式能力 | ⚠️ **部分支持**：handler 文档明示可 hold 响应（SSE 语义），另有 `registerUpgrade`（WebSocket）；但桌面端 client 的 fetch 经 **IPC 桥接**（webserver README 明示），流式响应在桥接上的行为未验证 | webServer handler/upgrade 接口文档 + README |
| 输出通道决策 | ✅ **长轮询**：`GET /terminal/read?id&after`（cursor 偏移 + 有界缓冲，≤15s hold）+ `POST input/resize/kill`；fetch 通道真机已验证，是唯一已实证通道；SSE/WS 留作后续优化 | 现有 fs-service 路由 + fetch 真机验证 |
| 沙箱对 PTY 的约束 | ✅ **不受限**：host 半进程直接 spawn PTY，不经过 `SandboxedFileSystem`；shell 白名单 + `isLocalRequest` + cwd `fs.resolve`+stat 校验与 write-text 同级 | fs-service 先例 |
| 官方 `ctx.terminals`（dsh-terminal） | ❌ **不消费**：owner 作用域绑定活跃 Agent，UI 插件不是 Agent，误用会破坏 agent 生命周期语义 | dsh-terminal 源码：terminals 服务按 owner 归属 agent session |

## 关键技术决策

### 1. PTY 依赖：node-pty@1.2.0-beta.15

- `package.json` dependencies 加 `node-pty@1.2.0-beta.15`（与发行版内置版本严格对齐）
- `build.mjs` host externals 追加 `'node-pty'`（运行时从宿主 node_modules 解析，不打进 bundle）
- **DI 注入**：host terminal 服务构造函数接受 pty factory，生产环境传真实 `node-pty.spawn`，测试传 fake（假会话同步产出数据，无需真实终端进程）

### 2. 通道：长轮询 read + POST 控制面

| 路由 | 方法 | 说明 |
|------|------|------|
| `/api/dsk-develop-ui/terminal/shells` | GET | 可用 shell 探测（白名单逐项存在性检查） |
| `/api/dsk-develop-ui/terminal/create` | POST | `{shell, cwd, cols, rows}` → 会话 id + 首帧 cursor |
| `/api/dsk-develop-ui/terminal/input` | POST | `{id, data}` 键盘输入 |
| `/api/dsk-develop-ui/terminal/resize` | POST | `{id, cols, rows}` |
| `/api/dsk-develop-ui/terminal/read` | GET | `?id&after=<cursor>` 长轮询，≤15s hold，返回 `{data, cursor, exited}` |
| `/api/dsk-develop-ui/terminal/kill` | POST | `{id}` 销毁会话 |

会话表内存持有（不持久化）；缓冲有界（超出丢弃最旧，cursor 单调递增）。

### 3. wt（Windows Terminal）不支持

**wt 是终端模拟器应用（独立 OS 窗口），不是可嵌入的 shell 进程**，无法挂进 xterm 面板。shell 白名单最终为：**powershell / pwsh / cmd / bash（Git Bash）**。交互设计 v1.9 中 wt 条目为文档差异，实现以 4 种为准（待回写交互设计）。
